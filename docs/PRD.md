## 1. TL;DR

**Seed** 是一款面向大学生和职场新人的 AI 自适应人才优势测评产品。用户通过 10 道基于经典心理学量表改编的选择题完成测评，系统利用 AI 自适应选题策略和加权计分算法生成六维能力画像（思维力、创造力、执行力、社交力、情绪力、驱动力），输出含证据链的可视化报告并支持社交分享。

**核心差异点**：不同于 MBTI 等静态测评，Seed 的 AI 不是出题者而是"选题者"——从 36 道科学验证的题库中自适应选择最具区分度的题目，降低测评疲劳的同时提高结果准确性。每项评分配有置信度区间和用户原话证据引用，避免"AI 幻觉报告"。

## 2. 产品目标

### 2.1 商业目标

| 目标 | 衡量指标 | 目标值（6 个月） |
|------|---------|----------------|
| 用户增长 | 月活用户 | 5,000 MAU |
| 注册转化 | 测评完成 → 注册率 | ≥ 25% |
| 社交裂变 | 分享链接生成率 | ≥ 15% |
| 用户留存 | 30 日回访率 | ≥ 20% |

### 2.2 用户目标

- **自我认知**：通过科学量表了解自己的六维能力画像
- **职业决策**：获得基于能力画像的职业方向推荐
- **社交分享**：将报告分享至社交圈，获得外部反馈
- **成长追踪**：多次测评后观察能力变化趋势（V2）

### 2.3 Non-Goals（明确不做）

| 不做 | 原因 |
|------|------|
| 临床心理诊断 | 非医疗产品，不做诊断声明 |
| 企业招聘筛选 | 不做人才筛选工具，避免公平性争议 |
| AI 生成题目 | 题目全部来自经学术验证的量表改编，AI 不出题 |
| 付费测评 | MVP 阶段全免费，专注增长和体验打磨 |
| 对比同龄人数据 | 需数据积累，V2 再做 |

## 3. 用户画像与故事

### 3.1 核心用户画像

#### Persona 1：迷茫的大学生 — 小林

- **年龄**：20 岁，广东工业大学大二
- **场景**：面临选专业方向 / 找实习，不确定自己适合什么

- **核心需求**：一份"有科学依据、能真正指导选择"的能力评估
- **JTBD**：当我在迷茫时，我想了解自己的真实优势，以便做出更明智的职业决策

#### Persona 2：考虑转型的职场新人 — Alex

- **年龄**：25 岁，工作 2 年，互联网运营
- **场景**：对现状不满，考虑转到产品或数据分析但不确定是否合适

- **行为**：主动搜索"职业测评"找到 Seed
- **核心需求**：一份能放进 portfolio 的专业能力解读
- **JTBD**：当我想转行时，我需要一份客观的能力评估来指导方向并增强自信

#### Persona 3：自我探索爱好者 — 小张

- **年龄**：23 岁，gap year 中
- **场景**：对星座/MBTI/盖洛普都有了解，追求更深入的理解
- **痛点**：现有工具要么太娱乐化要么太学术门槛高
- **行为**：在社群中看到 Seed 的学术量表改编说明，决定尝试
- **核心需求**：既科学又不枯燥的自我探索工具

## 4. 功能需求

### 4.1 功能模块

| 模块 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| **测评引擎** | 自适应选题 + 答案记录 | P0 | 轮巡基线 → 加权追问 → 收束算法 |
| **测评 UI** | 聊天式对话界面 | P0 | 移动优先，选项按钮在气泡中 |
| **注册系统** | 邮箱注册 / 登录 / JWT | P1 | 渐进式：3 题后触发注册引导 |
| **报告生成** | 六维雷达图 + 文字解读 + 证据链 | P0 | ECharts 实时渲染 |
| **职业推荐** | 基于能力画像的职业建议 | P1 | 思维力→分析师, 社交力→用户研究等映射 |
| **分享** | 生成 token 分享链接（30 天有效） | P1 | 底部"我也要测评"入口 |
| **历史** | 查看历史报告列表 | P2 | 简版分数列表 |

### 4.2 题库设计

| 属性 | 说明 |
|------|------|
| 总题数 | 36 题（MVP），可扩展至 60-80 题 |
| 改编来源 | 大五人格 IPIP-50（20 题）、RIASEC（10 题）、Grit 坚毅量表（8 题）、SDT 自我决定量表（8 题）、NFC 认知需求量表（6 题）、自编情境题（6 题） |
| 题目格式 | 5 级 Likert（非常不符合 ~ 非常符合） |
| 题目权重 | 改编自经典量表的题权重 0.9-1.0，自编题权重 0.7-0.8 |
| 反问题 | 12 道反向计分题（防惯性作答） |
| 存储格式 | JSON 文件，版本化管理（`questions.json`） |

## 5. 用户体验与关键流程

### 5.1 用户进入 → 完成报告的完整流程

```
用户A（新用户）：
  首页"开始测评" → 回答第 1-3 题（无需登录）
  → 第 3 题后弹出 Preview："你的思维力初步分数 78，想看完整六维报告吗？"
  → [注册/登录] → 继续回答第 4-10 题
  → 测评完成 → 自动跳转报告页 → 查看六维雷达图 + 各维度解读
  → [分享] → 生成分享链接 → 微信/朋友圈传播

用户B（从分享链接进入）：
  点击好友分享链接 → 查看简化报告（雷达图 + 总体摘要）
  → 拖到底部 → "我也要测评" → 跳转首页 → 开始测评
```

### 5.3 注册转化漏斗设计

```
体验 3 题 → Preview 1 个维度 → 注册引导弹窗
                                  ├─ [注册查看完整报告]  → 注册页
                                  └─ [继续测评]         → 接着答题

设计原理：
- 3 题投入了时间和好奇心 → 注册意愿比冷启动高
- 看到 1 个维度的真实分数 → 产生"想看完整体"的饥饿感
- "继续测评"选项 → 不强制，但做到第 10 题后还是会要求注册才能看完整报告
```

## 6. 叙事脚本：一天的生活

> **小林**是大二学生，晚上 11 点在宿舍刷手机，看到好友分享了一个 Seed 报告的链接。她点开看到好友的六维雷达图，底部写着"我也要测评"。她好奇地点了进去。

> 首页简洁——一个图标、一句话"发现你的天赋优势"、一个按钮"开始测评"。小林点了。

> 前三道题很快，每题一个情景判断，选项从"非常不符合"到"非常符合"。第 3 题答完后，AI 弹出一个卡片："你的思维力初步分数 78，想看完整六维报告吗？"下方两个按钮。小林用邮箱注册了。

> 注册后继续答题。每题的选择很顺滑，偶尔 AI 给一句即时反馈。到了第 10 题，系统提示"测评完成，正在生成报告..."。

> 报告页让小林眼前一亮——六维雷达图清晰直观，"思维力 85"的蓝色进度条超过其他维度。下方是每个维度的文字解读，还引用了她第 3 题的回答作为证据。最底部是职业方向推荐——产品经理 92%、管理咨询 87%。

> 小林点了"分享"按钮，把报告链接发到了朋友圈，附了一句"准不准？😏"。第二天早上，她发现 8 个朋友通过了她的链接做了测评。

## 7. AI 产品核心：6 层架构

> 以下 6 层是 AI PM PRD 区别于传统 PRD 的核心模块。

### 7.1 输入层：用户意图与上下文定义

#### 7.1.1 用户意图分类

| 意图类型 | 触发场景 | 系统响应策略 |
|---------|---------|------------|
| **开始测评** | 点击"开始测评"按钮 | 创建测评会话，返回第一题 |
| **继续答题** | 回答问题后获取下一题 | Agent 自适应选题 → 返回下一题或完成 |
| **查看报告** | 答题完成 / 从历史进入 | 调用分析引擎 → 生成/返回报告 |
| **分享报告** | 点击分享按钮 | 生成 token → 返回分享链接 |
| **查看分享** | 打开分享链接 | 无需登录，返回简化报告 |

#### 7.1.2 上下文管理

| 上下文类型 | 数据结构 | 使用场景 |
|-----------|---------|---------|
| 答题历史 | `[{question_id, answer_value, round_number, target_dimension}]` | 选题 Agent 判断下一步 |
| 维度覆盖 | `{thinking: 2, creativity: 0, ...}` | 选题策略（轮巡+加权） |
| 用户状态 | `{is_authenticated, session_id, current_round}` | 注册漏斗触发时机 |
| 评分中间态 | `{dimension: {score, confidence, answers_count}}` | 置信度收束判断 |

### 7.2 Prompt 策略层：系统提示词与 Prompt 工程

#### 7.2.1 选题 Agent Prompt 策略

> 注意：Seed 的 Agent 不是出题者，而是选题者。题库固定，AI 不生成题目文本。

**选题策略说明（用于 Agent 内部推理）**：

```
你是人才测评专家。你有一个 36 道选择题的题库，每道题标注了维度（thinking/creativity/execution/
social/emotional/drive）和权重（0.7-1.0）。

你的任务是根据用户的答题历史，选择最具区分度的下一道题。

选题策略：
1. Phase 1（前 6 题）：每个维度轮流各出 1 题，建立基线
2. Phase 2（第 7 题起）：对置信度 < 0.85 的维度加权多出题
3. Phase 3 收束条件：任一维度满足 (a) 置信度 >= 0.85 且已答 4+ 题 或 (b) 已答 8 题

输出格式：返回 question_id，不返回题目文本。
```

#### 7.2.2 报告生成 Prompt 策略

```
你是专业人才评估顾问。基于用户的六维评分数据，生成个性化报告。

约束：
- 每个维度的文字解读必须引用用户在该维度的具体答题情况作为证据
- 不得编造未在答题中体现的结论
- 正面表述为主，但需诚实反映低分维度的实际情况
- 职业建议必须基于评分数据，不得脱离数据推荐
- 使用平实、专业的中文，避免空洞形容词堆砌

输出格式：JSON
{
  "dimension": {
    "strengths": "string",
    "areas_for_improvement": "string", 
    "description": "string",
    "evidence": ["引用原题+用户回答"]
  }
}
```

#### 7.2.3 Prompt 版本管理

| 版本 | 变更内容 | 效果 |
|------|---------|------|
| v1.0 | 初始选题策略（轮巡+加权） | 基线 |
| v1.1（计划） | 增加"用户回答长度检测"，过短的回答可能触发追问题 | 提高回答质量 |
| v1.2（计划） | 增加职业建议的置信度说明 | 降低过度承诺 |

### 7.3 行为边界层：模型行为约束

#### 7.3.1 Agent 行为边界定义

| 行为 | 允许 | 禁止 |
|------|------|------|
| 生成题目文本 | ❌ | ✅ 题目必须从题库选取，不生成新题 |
| 修改题库权重 | ❌ | ✅ 权重固定，不动态调整 |
| 计分计算 | ❌ | ✅ 计分在确定性沙箱中执行，不由 LLM 计算 |
| 给出心理诊断 | ❌ | ✅ 不声称能诊断抑郁症/焦虑症等临床问题 |
| 推荐不适合的职业 | ❌ | ✅ 基于评分数据映射，不脱离数据推荐 |
| 文本解读 | ✅ | ❌ 允许 AI 基于评分数据生成个性化解读 |
| 职业建议 | ✅ | ❌ 允许 AI 基于画像推荐职业方向 |

#### 7.3.2 安全性约束

| 场景 | 策略 |
|------|------|
| 用户输入包含敏感个人信息（身份证号等） | 不存储到答题记录，提示用户注意隐私 |
| 用户表达自杀/自伤倾向 | 系统识别后提示"本产品不提供心理危机干预，请拨打 400-161-9995" |
| 用户恶意作答（全部选 1 或全部选 5） | 分析引擎做异常检测，标记为低置信度结果，报告中提示"检测到作答一致性过高，结果仅供参考" |

#### 7.3.3 隐私与数据

| 原则 | 实现 |
|------|------|
| 数据最小化 | 仅收集测评答题数据和邮箱，不收集姓名/手机号等 |
| 用户可控 | 用户可请求删除自己的全部数据 |
| 分享控制 | 分享仅公开报告摘要和雷达图，不泄露原始答题记录 |
| 加密存储 | 密码 bcrypt 哈希，JWT 鉴权 |

### 7.4 输出兜底层：降级与容错

#### 7.4.1 异常场景处理矩阵

| 异常场景 | 触发条件 | 兜底策略 | 用户可见 |
|---------|---------|---------|---------|
| **LLM API 超时** | Anthropic API > 10s 无响应 | 切换到模板化报告生成（预置文案） | 报告延迟标注"A" |
| **LLM 返回格式错误** | JSON 解析失败 | 重试 2 次 → 仍失败则用模板报告 | 报告无标注 |
| **题库文件丢失** | `questions.json` 不可读 | 使用硬编码的内置 10 道紧急题目 | 无感知 |
| **数据库不可用** | PostgreSQL 连接失败 | 返回 503，前端显示"系统维护中" | 明确提示 |
| **用户网络中断（答题中）** | SSE 连接断开 | 前端本地缓存最后答题状态，恢复后继续 | 提示"已恢复" |
| **异常作答检测** | 全部选相同选项 或 完成速度 < 30 秒 | 标记 low_confidence，报告中提示 | 报告中黄色标注 |
| **分享链接过期** | token 超过 30 天 | 返回 404 并提示"链接已过期，自己做一次吧" | 引导重新测评 |

#### 7.4.2 兜底报告模板

当 LLM 不可用时，系统使用预置的模板化报告：

```
维度：{dimension_label}
评分：{score}/100

{score >= 75}: "你在{label}方面表现出色。高分表明..."
{50 <= score < 75}: "你的{label}处于中等水平。建议..."
{score < 50}: "你在{label}方面有较大提升空间。可以尝试..."

说明：本报告由系统自动生成（非 AI 模型），可能不如个性化报告详细。
```

### 7.5 评估质量层：评估集与质量标准

#### 7.5.1 Agent 选题质量评估

| 评估维度 | 测试方法 | 通过标准 |
|---------|---------|---------|
| 轮巡覆盖 | 模拟 6 次选题，检查是否覆盖全部 6 个维度 | 6 题内 100% 覆盖 |
| 加权追问 | 给定某维度回答高度不一致（如 1/5/1/5），检查后续是否增加了该维度题量 | 是 |
| 收束时机 | 给定某维度 4 题回答高度一致（如全部 4-5），检查是否在合理轮次后停止追问 | 8 题内收束 |
| 题库穷尽 | 模拟极端场景（36 题全答完），检查是否正确返回 None | 不崩溃，返回完成 |

#### 7.5.2 报告生成质量评估

| 评估维度 | 测试方法 | 通过标准 |
|---------|---------|---------|
| **证据准确性** | 人工 review 10 份报告，检查文字解读是否引用了用户真实回答 | 引用准确率 > 90% |
| **报告一致性** | 同一份答题数据生成 3 次报告，检查评分是否一致 | 评分差异 < 5 分 |
| **文本质量** | 3 位评审阅读报告，对"是否专业""是否有帮助"打分 | 平均分 ≥ 4/5 |
| **无幻觉** | 检查报告中是否出现用户未提到的事实 | 0 幻觉 |
| **职业推荐合理性** | 给定已知 profile（如高思维力低社交力），检查推荐是否合理 | 前 3 推荐中包含匹配方向 |

#### 7.5.3 回归测试集

维护一个固定测试集（`tests/fixtures/` 下）：

| 用例 | 输入 | 期望输出 |
|------|------|---------|
| 全高回答 | 所有题选 4-5 | 各维度 > 70 分，置信度高 |
| 全低回答 | 所有题选 1-2 | 各维度 < 40 分，异常检测标红 |
| 混合回答 | 随机 1-5 | 各维度离散，置信度中等 |
| 极速作答 | 10 题 < 30 秒 | 标记为异常 |
