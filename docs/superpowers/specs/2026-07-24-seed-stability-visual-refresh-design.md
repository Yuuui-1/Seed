# Seed 稳定性修复与全流程视觉升级设计

## 目标

把 Seed 收敛为一个可部署、可演示、适合作品集展示的确定性产品流程：

`登录或注册 → 开始测评 → 完成 10 题 → 生成报告 → 查看、回顾和分享报告`

本次工作同时解决报告页不可用、匿名注册状态断裂、鉴权刷新递归、资源越权、全新环境无法测试及标准前端构建失败的问题，并统一五个核心页面的视觉语言。

## 范围

### 包含

- 强制登录后才能开始和继续测评。
- 为受保护页面增加真实生效的路由守卫，并保留登录前的目标地址。
- 统一报告标识语义，完成页、历史记录和分享操作均明确使用 `report_id`。
- 测评完成后由受鉴权、校验所有权的后端接口生成或返回报告。
- 防止 token 刷新请求再次触发刷新，保证同一时间最多只有一个刷新过程。
- 对开始测评、提交答案、查询进度、生成报告实施用户所有权校验。
- 补齐后端运行依赖和前端 TypeScript 构建配置。
- 为关键故障路径增加回归测试。
- 统一首页、登录/注册、测评、报告、历史记录页面的 Apple 式极简视觉。
- 保留移动端 PWA 能力和桌面端响应式布局。

### 不包含

- 匿名测评、匿名会话恢复和注册后绑定旧测评。
- 重写 Agent 选题或计分算法。
- 新增社交、支付、运营后台或新的量表维度。
- 更换 Vue、FastAPI、ECharts 或数据库技术栈。

## 产品流程

### 未登录用户

- 首页仍可了解产品价值，但“开始测评”会跳转登录页。
- 登录页提供登录和注册链接。
- 登录或注册成功后优先回到原目标地址；没有目标地址时回到首页。
- 直接访问测评、报告或历史页面时，路由守卫执行相同行为。

### 已登录用户

- 点击“开始测评”创建一个属于当前用户的新测评。
- 每次提交答案时，后端校验测评属于当前用户且仍在进行中。
- 第 10 题完成后，前端调用报告生成接口。
- 后端校验测评已完成且属于当前用户，以幂等方式创建或返回报告。
- 前端使用响应中的 `report_id` 跳转 `/report/{reportId}`。
- 历史记录同样使用 `report_id`，报告页只负责读取报告，不再猜测参数类型或隐式生成报告。

## 后端设计

### 测评鉴权

- `/assessment/start` 要求登录，创建记录时写入 `user_id`。
- `/{assessment_id}/answer` 和 `/{assessment_id}/progress` 要求登录。
- service 层查询同时匹配 `assessment_id` 与 `user_id`，不依赖路由层单独保证安全。
- 对不存在和不属于当前用户的资源使用相同的 404 响应，避免泄露 ID 是否存在。

### 报告生成和读取

- 报告生成接口继续接收 `assessment_id`，但只允许处理当前用户已完成的测评。
- 已存在报告时，仅在报告属于当前用户时返回。
- 生成成功响应明确包含 `id` 和 `assessment_id`。
- 报告详情、分享和历史记录始终使用 `report_id`。

### 错误处理

- 未认证返回 401。
- 资源不存在或不属于当前用户返回 404。
- 未完成测评请求生成报告返回 409，提示测评尚未完成。
- 重复生成是幂等成功，不创建第二份报告。

## 前端设计

### 鉴权与刷新

- 路由使用 `meta.requiresAuth` 和全局 `beforeEach` 守卫。
- 登录页读取安全的站内 `redirect` 参数，成功后恢复原路径。
- refresh 使用不带响应拦截器的独立 Axios 实例，或通过 `_retry` 标志跳过二次刷新。
- 并发 401 共享同一个刷新 Promise；刷新失败只清理一次会话并跳登录页。

### 报告数据流

- 测评完成事件触发 `generateReport(assessmentId)`。
- 成功后读取响应中的 `id` 并跳转 `/report/{id}`。
- `ReportView` 只调用 `getReport(reportId)`。
- 加载、失败、无权限和空数据均有明确页面状态，不出现无限转圈或静默空白。

### 视觉系统

- 品牌基调：温暖米白背景、近黑正文、低饱和 Seed 绿色、少量暖金色强调。
- 字体：优先系统无衬线字体，使用清晰的字号层级和较宽松行高。
- 卡片：轻边框、柔和阴影、16–24px 圆角；减少大面积纯色块。
- 动效：只保留 150–250ms 的淡入、位移和状态反馈，尊重 `prefers-reduced-motion`。
- 可访问性：可见焦点、足够对比度、44px 最小触控区域、语义化按钮和加载状态。

### 页面结构

- 首页：简洁品牌导航、核心价值主张、一个主 CTA、科学量表/自适应选题/证据报告三项可信度说明。
- 登录/注册：双栏或居中卡片布局，强化品牌文案、错误反馈和密码要求。
- 测评：顶部进度与退出入口，中部聚焦单题，底部答案选项；减少聊天消息堆叠造成的认知负担，同时保留 AI 引导语。
- 报告：个人摘要、六维雷达图、维度洞察卡、职业方向、分享与再次测评操作。
- 历史：清晰的报告列表、日期、最高优势和查看入口；为空时提供开始测评 CTA。

## 测试策略

### 后端

- 全新虚拟环境可按 `requirements.txt` 安装并收集测试。
- 未登录不能开始、回答或查询测评。
- 用户 A 不能回答、查询或生成用户 B 的测评。
- 未完成测评不能生成报告。
- 重复生成返回同一 `report_id`。
- 人为制造 `assessment_id != report_id`，证明详情接口严格按报告 ID 工作。

### 前端

- 路由守卫把未登录用户送往登录页并携带 redirect。
- 刷新接口 401 不会递归调用自身。
- 完成测评使用生成响应的 `report_id` 跳转。
- 报告页只读取报告详情，不隐式生成。
- 标准 `npm run build` 通过。

### 验收

- 后端完整测试套件通过。
- 前端类型检查与生产构建通过。
- 手动验证登录、10 题测评、报告、历史、分享和退出登录流程。
- 手机宽度与桌面宽度下核心页面无溢出、遮挡或不可点击元素。

## 发布方式

- 在 `agent/stabilize-and-polish-seed` 分支实施。
- 只提交本设计范围内的文件。
- 验证通过后推送到 `origin`。
- 创建以 `main` 为目标分支的 draft PR，说明根因、修复内容、视觉变化和验证命令。
- 最终合并由拥有仓库写权限的维护者确认。
